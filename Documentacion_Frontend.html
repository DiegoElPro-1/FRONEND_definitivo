1. 🏰 Introducción y Arquitectura General

Recycling Points es una aplicación web para la gestión de un programa de reciclaje con acumulación de puntos. Los usuarios registran entregas de materiales reciclables, acumulan puntos y pueden canjearlos por recompensas.

Arquitectura: SPA (Single Page Application) construida con React 18. Usa React Router 7 para la navegación del lado del cliente. El estado global se maneja con useReducer en lugar de Context o Redux. Hay 3 flujos independientes según el rol del usuario: administrador, encargado y superadmin.

Backend: AdonisJS (Node.js) en puerto 3333. Base de datos: MySQL.

Hosts:

  • Desarrollo: Frontend http://localhost:3000, Backend http://localhost:3333
  • Producción: https://backend-rp-arreglado-n8p8.onrender.com (fallback)

4.2 Sistema de Toasts

function useToast() {
  const [toasts, setToasts] = useState([]);
  const showToast = useCallback((msg, type = "success") => {
    const id = Date.now();
    setToasts(t => [...t, { id, msg, type }]);
  }, []);
  const remove = useCallback(id => setToasts(t => t.filter(x => x.id !== id)), []);
  return { toasts, showToast, remove };
}

Cada toast:

  • id: timestamp (único)
  • msg: texto del mensaje
  • type: success | error | warning | info
  • Se auto-destruye después de 3.2 segundos
  • Animación de entrada (slide-in) y salida (fade-out)

Usos estandarizados:

  • Crear: "X creado correctamente"
  • Editar: "Cambios guardados correctamente"

4.3 Control de Sesión y Roles

const [user, setUser] = useState(() => {
  const saved = sessionStorage.getItem("user");
  return saved ? JSON.parse(saved) : null;
});

El usuario se guarda en sessionStorage (se borra al cerrar la pestaña). El token JWT se guarda en localStorage (persiste hasta cerrar sesión).

Flujo de inicio de sesión:

  1. handleLogin(usuarioData) guarda en sessionStorage y redirige según rol
  2. En useEffect principal: si hay usuario (no encargado), carga usuarios y admins desde API
  3. Cada dato se transforma a formato interno: { id, nombre, email, telefono, rol, zona, pts, activo, av, fechaAlta }

Cierre de sesión:

  1. Llama a cerrarSesion() (DELETE /api/auth/cerrar-sesion)
  2. Limpia sessionStorage, localStorage
  3. Redirige a /login con window.location.replace()

5. 📡 Capa de Servicios — services/api.js

Único archivo de servicios. No existe auth.js ni entregas.js separados.

Configuración base:

const BASE_URL = process.env.REACT_APP_API_URL || 'https://backend-rp-arreglado-n8p8.onrender.com';

Función genérica request():

async function request(path, options = {}) {
  const headers = { 'Content-Type': 'application/json', ...options.headers };
  const token = localStorage.getItem("token");
  if (token) headers['Authorization'] = `Bearer ${token}`;

  const res = await fetch(`${BASE_URL}${path}`, { ...options, headers });

  if (!res.ok) {
    const err = await res.json().catch(() => ({}));
    throw new Error(err.mensaje || `Error ${res.status}`);
  }
  if (res.status === 204) return null;
  return res.json();
}

Cada llamada al backend:

  1. Establece Content-Type: application/json
  2. Adjunta token JWT en header Authorization
  3. Si error, lanza excepción con mensaje del backend
  4. Si 204 (sin contenido), retorna null

7. 🏀 Componentes Compartidos — components/

7.1 Sidebar.jsx — Barra lateral del Administrador

Menú colapsable con:

  • Dashboard (fijo, siempre visible)
  • Recompensas (fijo)
  • Supermercados (solo si user?.esSuperAdmin)
  • Usuarios (desplegable: Usuarios, Encargados, Administradores)

7.2 Topbar.jsx — Barra superior del Administrador

Muestra logo "Recycling Points" y avatar del perfil. El avatar se carga de localStorage("perfilFoto") y escucha el evento personalizado "perfilFoto" (disparado desde Perfil.jsx al actualizar la foto). Al hacer clic en el avatar, navega a /perfil.

7.3 ToastContainer.jsx — Contenedor de notificaciones

Renderiza los toasts en la esquina inferior derecha (fixed). Cada toast:

  • Tiene animación de entrada rec-toast-in (0.35s ease-out)
  • Se auto-destruye después de 3.2s con animación rec-toast-out
  • Muestra ícono según tipo: success (check), error (x), warning (triángulo), info (info)
  • Tiene botón de cierre manual
  • Colores predefinidos por tipo (verde, rojo, amarillo, azul)

7.4 LoadingSpinner.jsx — Spinner de carga

Spinner circular animado con texto y puntos que se incrementan cada 400ms. Soporta:

  • size: "sm" (24px), "md" (40px), "lg" (64px)
  • overlay: modo pantalla completa con fondo semitransparente y blur
  • text: texto personalizado debajo del spinner

7.5 MapPicker.jsx — Selector de ubicación

Modal con mapa interactivo Leaflet centrado en Popayán (2.4448, -76.6147).

  • Usa OpenStreetMap como proveedor de mapas
  • Nominatim para búsqueda de lugares (ej: "Terraplaza Popayán")
  • Pin central indica la posición seleccionada
  • Al arrastrar el mapa, se actualiza el centro via MapDragHandler
  • Al confirmar, devuelve (lat, lng)

7.6 UserShared.jsx — Utilidades compartidas

Contiene 5 exportaciones:

getRolCfg(rol): Devuelve configuración de color e ícono para un rol específico. Usa ROLES_CFG de data.js con fallback a defaults.

RolBadge({ rol }): Componente badge con color e ícono del rol. Ejemplo: Admin (azul), Usuario (verde), Aliado (naranja), Encargado (morado).

Toggle({ checked, onChange }): Switch de activar/desactivar usando Bootstrap form-check-input con CSS personalizado.

ModalDetalle({ user, onClose, onSave, showToast, todosMateriales }): Modal de edición genérico para cualquier rol. Características:

  • Muestra avatar con iniciales
  • Formulario con validación (nombre, email obligatorios)
  • Campos condicionales según rol: nombreEntidad (Aliado), puntoAsignado y pts (Encargado)
  • Selector de materiales (Aliado) con chips toggle
  • Toggle de estado activo/inactivo
  • Info solo lectura: fecha de alta, rol

TablaUsuarios({ lista, onToggle, onVer, onEliminar }): Tabla genérica con columnas:

  • Avatar + nombre + fecha de alta
  • Email
  • Rol (RolBadge)
  • Zona
  • Puntos
  • Estado (Toggle + badge)
  • Acciones: editar, eliminar

Muestra estado vacío con icono y mensaje cuando la lista está vacía.

          {view === "canjes" && <Canjes />}
          {view === "calendario" && <Calendario />}
          {view === "notificaciones" && <Notificaciones />}
          {view === "reportes" && <Reportes />}
          {view === "perfil" && <PerfilEncargado />}
        </div>
      </div>
    </div>
  );
}

No usa React Router. Usa un state view y renderizado condicional. Tiene su propio useReducer local independiente del admin.

15. ❓ Preguntas Clave para Entrevista

1. ¿Cómo se maneja el estado global?

Con useReducer en App.jsx. Define acciones tipo flux para CRUD de usuarios, admins, aliados, encargados, y estado de IA/puntos. El panel encargado tiene su propio reducer independiente dentro de PanelEncargado.jsx.

2. ¿Cómo se maneja la autenticación?

Token JWT en localStorage, datos de usuario en sessionStorage. App.jsx lee sessionStorage al montar. handleLogin() guarda y redirige según rol. handleLogout() llama al API, limpia storage y redirige a /login.

3. ¿Cómo se separan los roles?

Tres flujos condicionales en App.jsx según user.rolSeleccionado: encargado (ruta /encargado/*), superadmin (ruta /superadmin/*), administrador (ruta /dashboard, etc.). Cada uno con su propio layout y componentes.

4. ¿Cómo se comunican los componentes?

Por props drilling. No hay Context API, Redux ni Zustand. Los datos fluyen de App.jsx hacia abajo. El panel encargado usa props compartido y el panel admin usa el objeto shared. El toast se pasa como prop showToast.

5. ¿Cómo funciona el sistema de toasts?

Hook personalizado useToast() en App.jsx. Cada toast tiene id (timestamp), msg y type. Se auto-eliminan a los 3.2s con animaciones. ToastContainer los renderiza en posición fixed (esquina inferior derecha).

6. ¿Cómo se maneja la carga de datos inicial?

En el useEffect de App.jsx, cuando hay usuario (no encargado), carga usuarios y admins desde API y los transforma a formato interno. Los encargados cargan sus propios datos dentro de PanelEncargado.

7. ¿Cómo se manejan los mapas?

Leaflet con OpenStreetMap. MapPicker.jsx muestra un modal con mapa centrado en Popayán. Usa Nominatim para buscar lugares. El pin central marca la ubicación. Al confirmar, devuelve lat/lng.

8. ¿Cómo se calculan los puntos por estado del material?

ESTADO_MULTIPLIER: Bueno=1.0, Regular=0.75, Malo=0.5. Cada fila en RegistrarEntrega aplica el multiplicador a los puntos base del material. Se muestra "Base: X pts × Y".

9. ¿Qué diferencia hay entre el panel administrador y superadmin?

El superadmin reutiliza los mismos componentes del administrador pero sin la ruta "Recompensas". Además, en Encargados.jsx no ve el botón "Nuevo encargado" (oculto con {!user?.esSuperAdmin && (...)}).

10. ¿Qué APIs consume el frontend?

Todas pasan por services/api.js. Los endpoints se organizan por módulo: auth (/api/auth), usuario (/api/usuario), aliado (/api/aliado), admin (/api/admin), encargado (/api/encargado). Cada función usa la función genérica request() que maneja headers, token JWT y errores.

11. ¿Qué archivo contiene la lógica de servicios?

Solo services/api.js. No hay auth.js ni entregas.js separados. Todo está centralizado en un solo archivo de 429 líneas.

12. ¿Cómo se estructura el formulario de registro de entrega (encargado)?

Tres pasos en RegistrarEntrega.jsx: (1) buscar y seleccionar usuario, (2) agregar materiales con kg y estado (con multiplicador de puntos), (3) confirmar con fecha de vencimiento de puntos requerida y ver resumen.

13. ¿Cómo funciona el CRUD genérico de catálogos?

CrudCatalogo.jsx recibe título, definición de campos y funciones API. Renderiza tabla, modal de creación/edición y confirmación de eliminación de forma dinámica. Los 9 catálogos lo usan con diferentes configuraciones.

14. ¿Qué almacenamiento se usa para cada cosa?

sessionStorage: datos del usuario (se borra al cerrar pestaña). localStorage: token JWT, foto de perfil, estado de materiales (_estadosMat), estado de entrega (_estadoEntregaActual). No hay cookies.

15. ¿Cómo se maneja el cierre de sesión?

handleLogout() en App.jsx: llama a cerrarSesion() (DELETE /api/auth/cerrar-sesion), limpia sessionStorage y localStorage, setea user a null, redirige con window.location.replace("/login") para recargar la app desde cero.
